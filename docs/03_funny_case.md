# 05 · 案例复盘:一次把"占周期最多"误当"关键路径"的 lea 误判

> 归集项目:MCC26(ROMS-CoSiNE 性能优化)。完整证据:`01_tasks/完整证据链报告.md` §5.15 / §7 归因最终修正;任务日志 `tasks/README.md`(2026-08-09);实验作业 `118810714`(ABBA)。
> 为什么写它:这是整个项目里**最典型的一次"指标误导人 + 阿姆达尔扳回"完整案例**;方法论层面可复用,单独立档。

## 1. 一句话结论

**perf annotate 显示 `lea` 占 pre_step3d 运行时 40.6%(最大单项),一度把优化方向带向"减少 lea / 强制标量 / AoS / 指针自增";阿姆达尔分析 + 一个对照 ABBA 决定性证明 `lea` 是「隐藏延迟」(在空闲 AGU 周期顺带执行),不是关键路径——占周期最多 ≠ 关键路径。方向全闭环,提交版未变。**

## 2. 事件还原(2026-08-07 → 08-09)

1. **起点**:用户追问"到底是什么在吃吞吐",perf annotate 热区反汇编显示 pre_step3d 运行时 **lea 占 40.6%**(最大单项),另有 3,537 条 lea + 324 条 reg-reg movaps。
2. **直觉(错误的)**:"lea 占了 40.6% 周期 → AGU(地址计算单元,仅 2 个)饱和 → 削减 lea 就能提速"——据此推论"强制标量 / AoS 布局 / 指针自增"可治本,用户当时也被带进这个直觉。
3. **反击(阿姆达尔分析,用户扳回)**:lea 是**隐式并行**的:它与 FP/load 流水线并行,在 AGU 空闲周期"顺带执行";lea 占的是**已经空闲的资源**,不挤占关键路径。所以"占比高"≠"在关键路径上"。
4. **决定性证据链**:

| # | 证据 | 数据 | 判定 |
|---|---|---|---|
| ① | stalled-backend 计数 | 全程序 **14.8%**(若 AGU 饱和,stalled 应 50%+) | AGU 未饱和 → lea 有大量空闲周期可躲 |
| ② | **标量对照 ABBA**(job 118810714,`-no-vec`,A=fast2 向量 / B=fast2 标量) | lea 3537→2724(**−23%**),但**全程序慢 34.5%**(A=5:40.98/5:35.41 vs B=7:38.81/7:38.85,重复性完美) | lea 减 23% 的收益被标量化 FP 关键路径翻倍(1 条 mulpd→2 条 mulsd)完全淹没 → **lea 不是瓶颈,FP 关键路径才是** |
| ③ | 编译选项 | `-fno-alias`、`-qopt-ra-region-strategy=loop` 全无效(指令反增) | 编译器层无操作空间 |
| ④ | AoS/指针自增微基准 | ifort -O2 已自动做指针自增(多维 vs 局部 lea 相同);AoS 可减 lea 86%,但 lea 非瓶颈 → 零收益 | 结构改造无意义 |

5. **收口**:瓶颈 = FP 关键路径延迟 + 复合执行上限;lea 是并行重叠开销。fast2 已最优,lea/AGU/标量/AoS 四个方向全部闭环,提交版不变。同期还连带钉死了:前端假设被 frontend stall 0.04% 排除;FP 端口通过 FMA 减半机制解释 fast2 的 −6.2%(SAR/SD 类)。归因微架构证据闭环。

## 3. 为什么"40.6%"这么有欺骗性

- 它是热区里**最大的单一条目**,天然看起来像"罪魁祸首";
- 分析者容易把"指令占周期比例"直接映射成"若消除它则省这么多时间"——这是**只算了吞吐,没算并行**(把"占用"当"独占");
- 引擎发射饱和(IPC~1.9、stalled-backend 仅 14.8%)时,**任何"与关键路径并行"的指令都会显示高占比**,且越优化越虚高;
- 真正的裁判不是"占比",是**对照实验**(删它/改它,看全程序变快还是变慢)。

## 4. 可复用检查单(下次先跑这四步)

1. **先看 stalled 分类计数,再信 annotate 占比**:stalled-backend < 20% 时,任何"并行隐藏指令"(lea、movaps、地址计算)的占比基本都不是瓶颈;
2. **对"最大单项"做反证实验**:最小改动的对照(本案例 = `-no-vec`,减 lea 23% 但全局 +34.5%)——一票否决;
3. **阿姆达尔拆分**:指令分"关键路径串行链"(FP 依赖链)与"并行隐藏层"(AGU/延迟);只优化后者 = 零收益;
4. **"减指令但变慢"是最强的证伪信号**:说明被减的指令本来没占关键资源,减它反而破坏了编译器原本的调度。

## 5. 更大范围的启发

该案例与项目里另两个"归因修正"同构:①"memory-bound 带宽饱和"(64×1 慢 18.8% 的表面指标,perf 修正为指令吞吐 IPC 1.9 饱和);②"10 步 10.7%=AVX2 收益"(短时采样被启动热身放大,两次半天 ABBA 0.08%/0.21% 翻盘)。共同教训:**性能指标(占比/短测/直觉)必须先过"阿姆达尔 + 对照实验"两道闸,才允许进入优化决策**——本队后续所有候选都引入"保守整机 ceiling >2% 才允许作业"门禁,直接源自这系列教训。
