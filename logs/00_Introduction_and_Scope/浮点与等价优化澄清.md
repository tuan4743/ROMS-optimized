# 边界澄清：浮点顺序与等价实现

日期：2026-08-03。来源：组委会对队伍提问的直接回复（原始对话由队伍保存）。

## 可执行解释

1. 不要求位级一致。
2. 在物理公式/算法不变的前提下，浮点执行顺序可以变化；以官方精度范围（`vali.py` RMSE）达标为数值门槛。
3. 示例 `a+b+c` 可先计算任意子表达式；这说明等价重排、公共子表达式缓存、循环交换造成的累加顺序变化、MPI/OpenMP 归约树变化，以及由编译器产生的向量化/FMA，原则上属于正常通用优化。
4. “涉及数学公式的等价替换”可做，但不得把物理算法改成不同算法，也不得改变物理公式本身。
5. 组委会同时提醒：激进优化可能因精度超限而失败。因此 RMSE 通过是必要门槛；每个会改变浮点顺序的候选仍需完整 `2592/12960`、官方验证和源代码审查。

## 边界

- 仍禁止：改物理计算方案/公式、物理网格与网格大小、积分时间、时间步、输出语义、初始/边界/强迫/生态参数，关闭生态、减少变量、把双向嵌套变单向嵌套。
- 仍允许：MPI/OpenMP、循环组织、内存布局、编译器优化、通信实现、I/O 实现等正常通用优化，前提是上述边界和最终精度满足。
- 本澄清取代此前“浮点执行顺序待确认”与 `FP_ORDER_COMPLIANCE_PENDING` 的工作假设。

## 进一步口径：物理算法与计算机实现分离

组委会补充说明（2026-08-03）：气象/物理侧与计算机侧存在差异；他们要保证的是**物理计算公式、物理算法不被修改**，而计算机底层算法存在许多可调方法。

工作定义：

- **不可动**：物理/生态公式及其离散算法语义、网格问题本身、时间推进问题、双向嵌套语义、输入场和输出科学语义。
- **可动**：MPI 通信组织/数据打包/collective 实现、非阻塞或持久通信、线程和循环组织、数据布局/缓存/临时缓冲区、编译器与向量化、等价数学表达式实现、I/O 内部实现等计算机实现算法。
- **验收**：每项改动仍需保留物理算法语义、通过完整官方精度验证，并在源码审查中能说明其为计算机实现优化而非物理算法替换。
