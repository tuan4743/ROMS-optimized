## 3. 通信热点与优化对照（答辩 Q&A 素材）

### 3.1 halo 交换（mp_exchange）

- 模式：打包 → Irecv(先 W/E) → Send(W/E) → Wait → 解包；NS 同构。
- 为什么不能改：UCX 流水线已对此模式优化；实测 Isend+Waitall −50%（v24b）、Sendrecv −5%（v25）、持久请求 −59%（v26）、双缓冲 −100%（v28）。
- 2D 交换量小（ghost 列只有角点区），无重叠价值；3d/4d 每 k 层只传 Nghost 点，标量级。

### 3.2 嵌套收集（nesting + distribute）

- 原始：`get_contact2d/3d` 每 rank 填充自己 tile 的点（Aspv 哨兵）→ `mp_assemble` 全量 Allgather 4·Npoints 数组 → 取哨兵。粗网格每步末对 ζ/ubar/vbar/DU_avg2/t(17)/u/v 各做一次 → 每粗步 ~23 次 Allgather。
- 优化：稀疏 owner 模式（只通信有数据的 tile）→ 半天 7:50→6:43（v22 基线累积）；分层 Bcast（v24a）：Bcast 12.37%→1.81%（−85.4%），全量三天 38:58→38:15（−1.8%）。
- 细网格供给点分布（Stage 138 P0）：粗网格 100% contact 流量在 6 个中心 tile（rank 35/36/37/43/44/45）；细网格 100% 供给点在边界环（西列最重）→ 负载不均衡根源。

### 3.3 2D/3D 耦合串行路径

- `set_avg`（不可逆规约，tile 逆序）、`step2d` 末尾耦合、嵌套插值、打包 → 单线程段；32 MPI×4 比 64×2 明显更慢的原因（每 rank 线程数增加不能分摊这些串行段）。

## 4. 数值精度/等价性要点（答辩）

- 官方验证：26 变量 RMSE（Dongsha60 u 阈值 0.000060）；本队/队友全部有效优化保持位级一致或 u=5.2e-5。
- `-no-fma`：钉住浮点收缩行为，是 ifort2021 通过 vali 的关键（否则 fast 族超限 u=0.000062）。
- 组委会澄清：物理公式/算法不变时允许浮点顺序与数学等价实现变化；最终以完整官方 RMSE 验证为准。
- 轨迹哈希（trajectory SHA-256）作为 A/B 等价性门禁：ABBA 内 A/B 轨迹相同才可比较性能。
