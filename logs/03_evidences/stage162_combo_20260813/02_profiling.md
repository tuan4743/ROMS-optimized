# Stage 162 组合测试——性能刻画（2026-08-13）

## 1. 各子项独立收益回顾（夜间 AAB）

| 子项 | 平静 ABBA delta | 机制 |
|---|---|---|
| yield | −1.0~−2.6% | 轮询线程让核（user CPU −10%） |
| GLS precise | −0.30% | 向量化（4396 向量指令） |
| pinned | −0.32% | 用户缓冲不 unpin |
| HTMP1 | −0.13% | 热队并发 1 |
| UCX rc | −0.38% | IB DC→RC |

- 加和（线性）≈ −2.1~−3.8%；实测组合平静 −1.04% → **子项间存在重叠/抵消**（user CPU 降 10% 是 yield 主贡献，其余四项 ≈0）。
- 平静时段：同步受限结构吸收计算类收益（Stage 90 铁律），仅 yield 的"少烧 CPU"留 ~1%。

## 2. 争抢时段的新机理（首次量化）

- 争抢源：队友 nan_new_3day（4 节点 I/O 流量）/共享网络。
- A（busy-poll）：user 33m→142m（轮询在长等待中满速烧 CPU），real 100s→519s。
- B（yield）：user 30m→47m（yield 抑制轮询），real 100s→277s。
- **−45% 弹性**的机制：等待期间轮询线程少占核 → 本 rank 的另一线程与同节点邻居 rank 获得更多 CPU → 消息到达/推进更快 → 同步等待缩短。这是"降低无用 CPU 抢占 → 缩短同步等待"的路径，在争抢下被放大 40 倍。

## 3. 比赛适用性评估

- 比赛时多队并行 → 网络/存储共享争抢大概率存在 → yield 的弹性价值真实。
- 无争抢时 yield 成本 ≈ −0.5~1%（几乎零风险）。
- 轨迹位级一致 → 无需重跑 vali（实测 diff=0；但正式提交前建议一次全量确认）。

## 4. 结论

- 平静晋级：不达（1% < 3%）。
- 争抢保险：达（45%）且零风险。
