# 02 剖析与机理 — [O34] 四对象选择性 OpenMP

比较口径：**A2 vs B2**（两次热态运行），CPU-秒，Grid 01 + Grid 02 求和。
ROMS profile 的数字是 `cpu_time()` across 64 rank 的累加（Stage 88 已确立），
即"线程时间和"，不是墙钟。

## 1. 噪声标定：同一二进制的两次运行

先确认哪些差异是信号。同二进制重复性（Grid 02）：

| 计时器 | A1 | A2 | 相对差 | B1 | B2 | 相对差 |
|---|---|---|---|---|---|---|
| GLS vertical mixing | 983.523 | 974.689 | 0.91% | 1178.273 | 1171.033 | 0.62% |
| 3D halo exchanges | 251.683 | 247.061 | 1.87% | 303.342 | 298.683 | 1.56% |
| Corrector 3D momentum | 142.167 | 142.094 | 0.05% | 161.782 | 162.014 | 0.14% |
| Equation of state | 89.981 | 89.728 | 0.28% | 95.082 | 96.363 | 1.33% |

计算类计时器的运行间噪声 < 2%。下面 5%–22% 的 A→B 变化都是真信号。
例外：`Reading of input data`、`data broadcast`、`Processing of input data`
的运行间波动可达 ±40%，属文件缓存效应，单独讨论。

## 2. 四个目标区间：OpenMP 确实生效，且效率很高

| 计时器（目标） | A2 CPU-s | B2 CPU-s | 比值 | 隐含线程加速比 s |
|---|---|---|---|---|
| Equation of state (`rho_eos`) | 122.724 | 130.539 | 1.0637 | **1.880** |
| Biharmonic geopotentials (`hmixing`) | 124.777 | 131.569 | 1.0544 | **1.897** |
| 3D rhs terms (`rhs3d`) | 186.576 | 191.638 | 1.0271 | **1.947** |
| Corrector 3D momentum (`step3d_uv`) | 195.547 | 224.392 | 1.1475 | **1.743** |
| **四者合计** | **629.624** | **678.138** | **1.0771** | **1.857** |

推导：某区间在 A 中单线程（CPU = 墙钟），在 B 中双线程且两线程都忙
（CPU = 2 × 墙钟），则

    CPU_B / CPU_A = 2 × (墙钟_B / 墙钟_A) = 2 / s   ⟹   s = 2 / (CPU_B/CPU_A)

四个对象的 s 落在 1.74–1.95，**高于 O33 中既有 5 个 OpenMP 对象的平均
1.651**（Stage 88 用同一方法测得）。Stage 89 计划里担心的"线程效率不足"
并未发生，反而更好。

按此，四区间应节省的墙钟：

    串行墙钟 = 629.624 / 64 = 9.838 s/rank  （占 A2 墙钟 124.457 s 的 7.90%）
    并行后   = 9.838 / 1.857 = 5.298 s/rank
    应省     = 4.540 s/rank = 全程墙钟的 3.65%

## 3. 但整机墙钟没动：省下的时间全部变成了别处的等待

A2 → B2 总 CPU：10138.0 → 10598.5 CPU-s，**+460.5（+4.54%）**；
其中四个目标区间只贡献 +48.5，**未改动区间净增 +412.0 CPU-s = +6.44 CPU-s/rank**。

未改动区间的 CPU 变化（A2 → B2，G1+G2）：

| 计时器 | A2 | B2 | 变化 | 备注 |
|---|---|---|---|---|
| GLS vertical mixing | 1356.027 | 1637.413 | **+281.4 (+20.8%)** | 已是双线程；区内含 3-D 交换 |
| 3D halo exchanges | 323.210 | 395.588 | **+72.4 (+22.4%)** | 串行；部分嵌套于计算计时器内 |
| 4D halo exchanges | 875.021 | 927.390 | +52.4 (+6.0%) | 串行 |
| 2D halo exchanges | 628.376 | 663.784 | +35.4 (+5.6%) | 噪声较大（B1 613.9） |
| Omega vertical velocity | 60.206 | 69.521 | **+9.3 (+15.5%)** | 串行，紧邻被改区间 |
| 2D/3D coupling | 99.144 | 106.447 | +7.3 (+7.4%) | 串行 |
| 3D predictor (`pre_step3d`) | 1787.217 | 1810.478 | +23.3 (+1.3%) | 已是双线程 |
| Corrector tracers (`step3d_t`) | 1417.681 | 1424.534 | +6.9 (+0.5%) | 已是双线程 |
| Model 2D kernel (`step2d`) | 1335.558 | 1326.065 | −9.5 (−0.7%) | 串行，未受影响 |
| Biology / t3dmix4_s / PG / 应力张量 | — | — | ±0.3% | 无变化 |

模式非常清楚：**增长集中在含 MPI 同步的区间**（GLS、3-D/4-D halo、
Omega、2D/3D coupling），而纯计算区间（step2d、t3dmix4_s、biology、
压力梯度）纹丝不动。

机理：`KMP_BLOCKTIME=0` 保证 OpenMP 空闲线程休眠、不烧 CPU；而 HPC-X/UCX 的
`MPI_Waitall` 是忙轮询，等待时间按 100% CPU 计入当时活跃的 wclock 区间。
Stage 88 已确认 message 计时器部分嵌套在计算计时器内部，所以 GLS 的 +20.8%
与 3-D halo 的 +22.4% 是同一批等待被记了两次，不能简单相加。

结论：四个区间快了 4.54 s/rank，全部在下一个同步点被等回去了。
GLS 一项就吃掉 281.4/64/2 = **2.20 s/rank**（约占节省量的一半）。

## 4. 全局记账闭合检验

把 CPU 变化折回墙钟（已是双线程的区间除以 2，串行区间除以 1），
检验两个互斥假设：

- 未改动的双线程区间：(281.4 + 3.6 − 0.3 + 23.3 + 6.9) / 2 = **+157.4 墙钟-s**
- 未改动的串行区间（含 I/O 项）：≈ **+202.7 墙钟-s**

**假设 H1（s = 1.857，OpenMP 真的生效）**
四区间墙钟变化 = 678.138/2 − 629.624 = **−290.6 墙钟-s**
预测总变化 = 157.4 + 202.7 − 290.6 = +69.5 墙钟-s = **+1.09 s/rank**
实测 = 125.012 − 124.457 = **+0.555 s/rank** ✔（差值在 I/O 项 ±1 s/rank 波动内）

**假设 H2（s ≈ 1，第二线程基本空转、区间墙钟没变）**
四区间墙钟变化 = 0
预测总变化 = 157.4 + 202.7 = +360.1 墙钟-s = **+5.63 s/rank** ⟹ B2 应为 130.1 s
实测 125.0 s ✘（差 5 s，远超噪声）

H2 被排除。**OpenMP 确实把这四个区间跑快了近一倍，只是整机没有因此变快。**

## 5. 全局线程占用率

| | 总 CPU-s | 墙钟 (s) | CPU / (64 × 墙钟) |
|---|---|---|---|
| A2 (O33) | 10138.0 | 124.457 | 1.2727 |
| B2 (O34) | 10598.5 | 125.012 | 1.3247 |

平均线程占用从 1.273 升到 1.325（+0.052），与"四区间占 7.9% 墙钟、
新增约 0.9 个有效线程"的量级一致。同时 12 个采样 rank 的 CPU 离散度
A2 为 155.3–159.5（2.7%）、B2 为 162.3–166.6（2.6%），**rank 间 CPU 离散度
没有变化** —— 忙轮询让等待方也满载，所以 CPU 均衡不能作为负载均衡的证据。

## 6. 机理判定

在 64 rank × 2 线程、8×8 分块、本平台上，整机墙钟不由单线程 3-D 计算决定。
四个对象合计 7.9% 的墙钟被压缩到 4.2%，理论 3.65% 的收益 100% 被同步等待吸收。
换言之：**这四个区间不在关键路径上**，关键路径由 rank 到达同步点的偏斜
（arrival skew）决定，而该偏斜与这四个区间无关。
